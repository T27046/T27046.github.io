前言#

文档说明#

本教程按“先会用、再查全”的顺序编写：第 2、3 章带你把界面认全并做出第一个脚本；第 4 至 6 章是图形化编辑、积木和脚本语言的完整参考；第 7 至 9 章讲运行调试、识别与文件；第 10 章给出可直接套用的实战案例；第 11 章与附录用于排错和速查。

阅读约定：

  • 积木：图形化编辑页里的彩色块，是脚本的图形形态。
  • 代码：代码编辑页里的文本脚本，也是积木最终生成的形态。
  • 槽位：同一个脚本文件里的多个独立脚本，可单独运行，也可一次运行全部。
  • 参数框里既可以填数字，也可以填 $变量 或表达式；文中统一用 $name 表示变量。
  • 代码块中的缩进只是为了阅读，脚本本身不依赖缩进。

适合谁读：初次接触脚本编辑器的用户，建议按第 2、3 章的顺序操作一遍；已经会搭积木、只想查参数的用户，可以直接翻到第 5、6 章；脚本不按预期运行时，先看第 11 章。

关于示例：书中的坐标、窗口标题、图片文件名都是示例值，复制后要替换成自己环境里的值。积木模式会自动把图片内嵌进脚本；代码模式里的 find_image("...") 需要写真实存在的文件路径。所有代码块都可以直接粘贴到代码编辑页。

关于版本：程序仍在持续更新，积木名称、界面布局和个别行为可能随版本变化。本手册以写作时的仓库代码为准；如果发现文字与界面不一致，以实际程序为准，并优先参考日志里的提示。

提示

第一次使用建议先读第 2、3 章，跟着做一遍；遇到具体积木再查第 5 章，遇到写法问题查第 6 章。

第 1 章认识脚本编辑器#

1.1它是什么#

脚本编辑器是 9o0d 鼠标连点器中的自动化工具。它把“移动鼠标、按下按键、等待、判断、循环、找图、找字”等动作编排成脚本，由程序在后台解释执行，并通过 Windows 的 SendInput 接口驱动真实的鼠标和键盘。

同一个脚本有两种编辑方式：

  • 图形化编辑：从右侧面板拖积木，适合不写代码的用户。
  • 代码编辑：直接书写脚本语言，适合精细控制、批量修改和复制片段。

两种方式可以互转：切到代码页时，积木会生成代码；切回图形页时，代码会重新解析成积木。解析失败时会留在代码页，并在日志里说明原因。

1.2能做什么#

类别 能力
鼠标 移动到坐标（6 种移动方式）、方向移动、相对移动、按下/抬起/点击、滚轮、拖拽
键盘 按下/抬起、组合键、逐字输入文本
流程 计数循环、条件循环、条件分支、跳出/继续、自定义函数
识别 屏幕找图（模板匹配）、找字（OCR）、取像素颜色、查找窗口
系统 执行 CMD、窗口激活/关闭/最小化/最大化/移动/缩放、剪贴板、音量、亮度
数据 变量、数学运算、随机数、字符串拼接、比较、逻辑运算
运行 多槽位、运行全部、倍速、断点、条件断点、单步、变量监视、日志
注意

脚本驱动的是真实输入。运行前请把鼠标放到安全位置，不要在无人看管时运行会点击付款、删除、提交等危险按钮的脚本。

1.3两种打开方式#

  1. 主程序：更多功能 → 快捷脚本。该功能需要高级通行证。
  2. 双击脚本文件：已关联时，双击 .9mc 会直接打开脚本编辑器并载入该文件。

进入后主窗口会切换为脚本编辑器模式：最小 1100×650，可缩放、可最大化，标题栏出现“运行 / 导出 / 导入”。离开该页后窗口恢复为 820×450 的固定尺寸。

1.4运行环境与权限#

  • Windows 10 / 11 x64，需要 .NET Framework 4.7.2 或更高版本。
  • “查找文本”依赖 Windows 自带的 OCR，需要系统安装对应语言包；程序优先使用简体中文，其次英文。
  • “查找图像”依赖 OpenCV 运行库，安装包已自带。
  • 如果目标程序以管理员身份运行，脚本编辑器也要以管理员身份启动，否则输入可能被系统拦截（UIPI）。
  • 多显示器、125% / 150% 缩放均可使用；脚本中的坐标统一按物理像素处理。

第 2 章界面总览#

2.1窗口与标题栏#

进入脚本编辑器后，主窗口标题栏中间会出现三个按钮：

按钮 作用
运行 运行当前槽位的脚本；运行期间按钮不可用
导出 打开保存对话框，保存当前脚本
导入 打开文件对话框，加载脚本或录制文件
提示

页面底部工具条上的“运行”按钮是隐藏的。运行当前脚本请点标题栏的“运行”；“运行全部”和“停止”在页面底部。

2.2图形化编辑页#

图形化编辑页从左到右分为四栏：

区域 位置 内容
变量/表达式栏 最左 自动列出脚本中出现的变量（坐标变量拆成 .x / .y），可手动添加变量，可把变量或随机数芯片拖进参数框
工作区 中间 积木树。空工作区会提示“拖拽右侧积木到此处”
积木面板 右侧 38 个积木入口，分执行、控制、循环、变量、其他、数学六类，顶部有搜索框
快速跳转栏 最右 六个分类按钮，点击后滚到积木面板对应分组

积木面板顶部搜索框支持按中文名或命令名实时筛选；右侧的“+”取点按钮、下拉框、按键框、图片槽位都直接嵌在积木上，改完即生效。

2.3代码编辑页#

代码编辑页由四部分组成：

  • 查找/替换栏：默认隐藏，Ctrl+F 打开查找，Ctrl+H 打开替换，Esc 关闭。
  • 语法检查栏：左侧“检查语法”按钮，右侧显示“✓ 语法正确”或“✗ 第 N 行: 原因”。
  • 编辑器：带行号、语法高亮、自动补全；横向不换行，长行用滚动条查看。
  • 右侧栏：上方是语法参考（move、循环、等待、变量、函数等示例），下方是运行时的变量监视面板。

2.4底部工具条#

控件 说明
槽位下拉框 切换当前脚本；切换时自动保存当前槽位
+ / × / 改名 新增 / 删除当前槽位、重命名当前槽位；重名会自动追加序号，至少保留一个槽位
运行全部 从第 1 个槽位开始依次运行；某个槽位出错就停止，不再继续
停止 中断正在运行的脚本；断点暂停时也能停止
单步 断点暂停后可用，执行下一条语句后再次暂停
继续 从断点恢复，直到下一个断点或脚本结束
速度 0.25x / 0.5x / 1x / 2x / 4x，运行中也可切换

主程序窗口底部右侧还有“收藏”和“添加桌面”两个按钮：前者把“快捷脚本”加入主页收藏，后者在桌面创建直达脚本编辑器的快捷方式。

2.5日志栏#

窗口最下方是 60 像素高的日志栏，记录：

  • 引擎日志（带时间戳）：移动、点击、等待、查找结果、循环次数、错误等。
  • 界面提示：保存、加载、断点、语法检查、槽位切换等。

“运行”会先清空日志，方便只看本次执行。出错时日志会给出具体行号和原因。

2.6快捷键#

位置 快捷键 作用
图形化 Ctrl+Z / Ctrl+Y 撤销 / 重做
图形化 Ctrl+C / Ctrl+V 复制 / 粘贴（以最近右键点过的积木为基准）
代码 Ctrl+F / Ctrl+H 查找 / 替换
代码 Ctrl+/ 注释或取消注释选中行（无选中则当前行）
代码 Esc 关闭查找栏
代码 Enter / Tab 确认自动补全候选
代码 Ctrl+Shift+S 检查语法
注意

代码页按 Ctrl+Shift+S 或点“检查语法”按钮，都可以检查语法并高亮错误行。

3.3运行与观察#

点“运行”后，日志会逐条打印执行过程；标题栏的“运行”变灰，底部“停止”变红。要中断就点“停止”，正在进行的移动也会被取消。

3.4保存与再次打开#

点标题栏“导出”，在保存对话框里选择格式：

  • .9mcp：脚本包，保存全部槽位、积木树、自定义变量和内嵌图片，推荐日常使用。
  • .9mc：纯文本脚本，只保存当前槽位的代码，适合分享片段。
  • .txt：纯文本，便于用其他编辑器查看。

再次打开时点“导入”，或直接双击 .9mc 文件。

3.5再进一步#

  • 把“等待”换成“等待直到 → 存在窗口”，就能等目标窗口出现后再操作。
  • 给循环加“条件分支”，就能按变量值决定继续还是跳出。

第 4 章图形化编辑详解#

4.1添加积木#

  • 从右侧面板拖到工作区：按住积木按钮拖到工作区，松手即插入。
  • 用搜索框：输入“找图”“循环”“窗口”等中文名，或 move、loop 等命令名，面板只显示匹配项；点搜索框右侧的 × 清空。
  • 收藏常用积木：右键面板中的积木 → “收藏”，它会出现在搜索框下方的“★ 收藏”区；再次右键可取消收藏。
  • 用快速跳转栏：点“执行 / 控制 / 变量 / 循环 / 其他 / 数学”，面板滚到对应分类。
  • 在容器内添加：循环、条件、函数积木内部有“+ 添加积木”按钮，也可直接把积木拖进去。

4.2排序与嵌套#

  • 拖动积木到目标位置，出现蓝色插入线时松手，即插入到该位置。
  • 拖到循环、条件、函数容器内部，会成为它的子积木。
  • 条件积木有 if 和 else 两个容器；没有 else 时可点“添加 else”。
  • 容器积木左上角的 ▾ / ▸ 可以折叠或展开子积木，长脚本更清爽。
  • 拖到工作区根列表的空白处，会插入到列表末尾。

4.3参数输入框#

积木上的白色小输入框既可以填数字，也可以填变量或表达式，最终会原样拼进代码：

  • 数字：100、1.5、-20。
  • 变量：$ctr.x、$pos.y、$count。
  • 表达式：random(1, 100)、add($n, 1)、concat($s, "后缀")（函数名区分大小写，建议全小写）。

如果填了拼写错误的内容，语法检查或运行时会在日志里报错。含中文或空格的值，在代码模式下需要用双引号包起来。

4.4屏幕取点#

所有需要绝对屏幕坐标的积木大多带 ＋取点 按钮：

  • 点击后出现全屏十字准星，移动鼠标对准目标，按左键单击即捕获，按 Esc 取消。
  • 坐标以物理像素为单位，主屏左上角为 (0, 0)，左侧或上方副屏为负值；多屏和缩放都不需要手工换算。
  • “鼠标拖拽”有两个取点按钮，分别填起点和终点；“像素颜色”的取点填 PixelX / PixelY。
  • “查找文本/图像”的“参考”坐标也有取点按钮，它决定“离哪个点最近”的匹配优先。
  • “窗口控制”的移动 / 调整大小参数目前没有取点按钮，需要手动填写坐标或尺寸。
注意

取点捕获的是当前屏幕位置。如果目标窗口会移动，或系统缩放改变，运行前要重新取点。

4.5按键捕获#

键盘按下/抬起、组合键、等待条件里的“键盘按下”都使用按键捕获框：

  1. 点击输入框，框内显示“按下按键…”。
  2. 按下要绑定的键，框内显示键名（如 A、Space、F5），底层保存的是虚拟键码。
  3. 按 Esc 取消本次捕获，保留原来的键。
  4. 单独按 Ctrl / Shift / Alt / Win 不会生效，必须再按一个主键；组合键请用“组合键”积木，或给“键盘按下”添加多个键框。

4.6图片槽位#

“查找图像坐标”“等待直到 → 检测到图像”“循环直到 → 检测到图像”都有图片槽位：

  • 点击槽位，选择一张本地图片；或把图片文件（png / jpg / jpeg / bmp / gif）直接拖到槽位上。
  • 图片会自动转成 PNG 并以 base64 内嵌进脚本，不依赖原文件路径。
  • 槽位显示 [嵌入图像] 或文件名；缩略信息不显示时，重新选择即可。
提示

截图要只包含目标本身，边缘不要带无关背景，也不要包含会变化的时间、数字、动画区域，否则相似度会被拉低。

4.7注释与折叠#

  • Shift + 点击积木：切换注释状态。被注释的积木半透明显示，生成代码时每行前加 //，运行时跳过。
  • 注释积木：专门用于写说明；Shift + 点击注释积木时，如果注释内容本身是一条可解析的语句，会尝试还原成对应积木。

5.7重点积木详解#

5.7.1移动与耗时#

  • “瞬移”直接跳到目标点，耗时参数不参与；其余模式按耗时插值，耗时被速度倍率整除（2x 时 600ms 实际约 300ms）。
  • 不填耗时时，移动默认 20ms；曲线/平滑模式建议 300–800ms，过短会退化成近似瞬移。
  • “向方向移动”始终是瞬时移动，不受耗时影响；需要动画请用“相对移动”。
  • “相对移动”始终把模式和耗时写进代码（例如 move_rel 50, -30, linear, 800），界面填写的耗时不会被省略；耗时为空的按 500ms 处理。

5.7.2查找图像坐标#

  • 原理：截取整个虚拟屏幕，转灰度，用归一化互相关做模板匹配，取相似度超过阈值且离参考点最近的匹配中心。
  • 阈值默认 0.70，范围 0–1。界面越稳定、截图越干净，阈值可以越高（0.85–0.95）；光照或压缩变化大时适当降低（0.65–0.75）。
  • 找不到时直接抛出运行时错误，脚本会停下；如果只是“等它出现”，请先用“等待直到 → 检测到图像”，或把查找放进“循环直到”里。
  • 不支持缩放和旋转匹配。换了分辨率、缩放比例或窗口大小后，需要重新截图。
  • 日志会打印找到的位置和相似度；相似度接近阈值却找不到时，优先重新裁剪截图，而不是盲目降低阈值。

5.7.3等待直到与循环直到#

七种条件的参数与轮询间隔：

条件 参数 轮询 说明
U 盘插入 无 500ms 以开始等待时的可移动磁盘数量为基准，数量增加才算插入
检测到文本 文本, 参考X, 参考Y 500ms 全屏 OCR，匹配离参考点最近的结果
检测到图像 图片, 参考X, 参考Y, 阈值 500ms 全屏模板匹配
键盘按下 虚拟键码 50ms 用 GetAsyncKeyState 轮询，极短的敲击可能漏掉

鼠标移动超过 距离（像素） 50ms 以第一次检查时的鼠标位置为基准，移动距离大于该值才算成立

  • 超时单位是毫秒，填 0 或留空表示无限等待；超时会抛出运行时错误，脚本停止。
  • “循环直到”先判断条件，条件已成立时循环体一次也不执行；不是“至少执行一次”。
  • “等待直到”只等待、不执行动作；“循环直到”在等待期间反复执行循环体。
注意

“存在窗口”先按完整标题精确匹配，找不到再按“包含该文本”匹配第一个窗口。窗口标题会随文档名、页码变化（例如“无标题 - 记事本”），只写一段能唯一识别的标题也可以；为避免误匹配，标题越完整越稳妥。

5.7.4条件分支#

  • 界面上的“如果 A 运算符 B”会生成 compare(A, "运算符", B)；运算符是字符串，必须带双引号。
  • 条件表达式的值非 0 即视为真；compare 返回 1 或 0，所以可以直接作为条件。
  • 需要“与 / 或 / 非”时，用逻辑积木先生成变量，或直接在条件里写 and(compare(...), compare(...))。
  • else 分支可以为空；空 else 也会生成 else 和 endif。

5.7.5窗口控制#

  • 标题先按完整标题查找，找不到再按“包含该文本”查找第一个匹配窗口。
  • “激活”会把窗口置前；“关闭”发送 WM_CLOSE，不等待真正关闭；“最小化 / 最大化”立即生效。
  • “移动”填屏幕坐标 x, y，窗口大小保持不变；“调整大小”填宽、高，左上角保持不变。
  • 目标窗口最小化时先激活再操作，避免看不到效果。

5.7.6输入文本与组合键#

  • “输入文本”逐字发送，间隔默认 30ms；间隔太小可能被目标程序丢弃，太大则明显变慢。
  • 文本以 $ 开头会被当作变量（例如填 $name 输入变量的值）。如果就是要输入以 $ 开头的原文，请在代码模式写 type_text "$100"。
  • “组合键”保存的是虚拟键码串，如 17+65（Ctrl+A）、17+86（Ctrl+V）。按下顺序从左到右，释放顺序从右到左，中间没有额外延迟；个别程序需要更慢的节奏时，改用多条“键盘按下 / 抬起”并插入“等待”。
  • 键码是十进制。常用键码见附录 A。

5.7.7比较与逻辑#

  • 两边都是数字时按数值比较；只要有一边是字符串，就按字符串序数比较并忽略大小写。
  • 字符串比较使用 string.Compare 的序数规则，中文按 Unicode 编码顺序，不适合做“拼音排序”。
  • and / or 有短路：左边已经能决定结果时，右边不会求值。
  • 逻辑和比较都返回数字 1 / 0，可直接参与数学运算或作为条件。

6.1书写规则#

  • 关键字建议全小写；多数关键字也接受首字母大写（如 Move、Loop），但不要全大写。
  • 注释用 //，可独占一行，也可写在行尾。
  • 字符串用双引号，支持转义：\n 换行、\t 制表、\" 引号、\\ 反斜杠。
  • 数字支持整数、小数和负号，例如 100、1.5、-20。
  • 变量以 $ 开头，后面可以是字母、数字、下划线；变量名区分大小写。
  • 语句之间不要用分号分隔；一行写两条语句会解析失败。

6.3语句详解#

6.3.1移动与点击#

  • move 省略模式时为瞬移，此时耗时参数即使写了也不参与。
  • click 等价于同一瞬间的按下 + 抬起，适合不需要按住时长的场景。
  • drag 会先瞬移到起点，按下，再线性移动到终点，最后抬起；拖拽过程中无法插入等待。

6.3.2等待与条件#

参数顺序必须与条件匹配：

  • usb：只有超时，wait_until usb, 10000。
  • text：文本、参考 X、参考 Y、超时。
  • image：图片、参考 X、参考 Y、阈值、超时；要写超时就必须先写阈值。
  • key：键码、超时。
  • mouse：按键、超时。
  • mouse_moved：距离、超时。
  • window：完整标题、超时。

loop_until 的参数与 wait_until 相同，只是超时之后要跟循环体，并以 endloop 结束。

6.3.3循环、条件与函数#

  • break / continue 只影响最近一层循环；在 if 里也能用，异常会被外层循环捕获。
  • 函数定义会在执行前统一收集，因此可以先 call 后 func；函数之间共享全局变量，没有局部变量。
  • 函数不能带参数，也不能返回值；需要“参数”时，用全局变量在调用前赋值。

6.3.4系统操作#

  • window 的动作为 activate / close / minimize / maximize / move / resize；move 和 resize 必须带两个数字参数。
  • cmd 与 cmd_capture 都通过 cmd.exe /c 执行；前者把输出写到日志，后者只把标准输出存入变量（标准错误丢弃）。
  • 命令里含双引号时写成 \"，例如 cmd "echo \"hello\""。
  • 剪贴板操作在脚本线程执行，剪贴板被其他程序占用时可能失败；读取失败会得到空字符串。

第 7 章运行、槽位与调试#

7.1槽位管理#

  • 一个脚本文件可以包含多个槽位，适合把“登录、日常、退出”等流程分开维护。
  • 点 + 新增（自动命名“脚本 N”），点“改名”重命名当前槽位，点 × 删除当前槽位；至少保留一个。
  • 切换槽位时自动保存当前槽位的积木与代码，再载入目标槽位。
  • 槽位名称最多 40 个字符，会随脚本包一起保存；重名时自动追加序号，下拉框里不会出现两个同名槽位。
  • “运行全部”从第 1 个槽位开始，跳过空槽位；某个槽位出错就停止，后面的槽位不再执行。

7.2运行与停止#

  • 标题栏“运行”运行当前槽位；如果当前在图形化页，会先把积木生成代码再执行。
  • 工作区没有积木，或代码为空时，只提示不运行。
  • 运行会清空日志、清空变量监视，并在后台线程执行，界面不冻结。
  • “停止”会取消执行令牌：等待会被立即打断，移动中的鼠标操作也会尽快停止；如果正处于断点暂停，会先恢复再取消。
  • 运行中“运行”不可用，“停止”可用；运行结束后自动恢复。

7.3速度倍率#

速度下拉框影响以下耗时：

  • wait 的等待时长。
  • move / drag / move_rel 的移动耗时。
  • type_text 的字间间隔。

不影响：等待条件的轮询间隔、点击按下的持续时长（按下与抬起之间的间隔由脚本自己控制）、cmd 的执行时间。运行中切换速度会立即生效。

7.4断点#

  • 右键积木 → “设置断点”，积木左侧出现红点；再次右键可移除。
  • 脚本执行到该积木的第一行时暂停，日志显示“🔴 [断点] 第 N 行暂停”，底部“单步”“继续”变为可用。
  • 暂停期间可以查看变量监视、切换代码页查看执行行，也可以直接“停止”。
注意

循环、条件、函数内部的嵌套积木也可以设置断点，运行到对应语句时会正常暂停。被 Shift+Click 注释（禁用）的积木整块不会执行，其内部断点也不会触发；另外断点行号是按积木生成的代码计算的，如果代码页被手工大改，行号可能对不上，建议在图形页设置断点。

7.5条件断点#

  • 先设置断点，再右键 → “设置条件…”，输入表达式。
  • 表达式为真（非 0）时才暂停；为空表示无条件断点。
  • 条件里可以用变量和函数，例如 compare($i, "==", 5)、compare($pos.x, ">", 1000)。
  • 条件写错时，日志提示“条件求值失败”，并按无条件断点处理，避免脚本卡死。

7.6单步与继续#

  • 命中断点后点“单步”：执行下一条语句，然后再次暂停。
  • 点“继续”：不再逐步暂停，直到下一个断点或脚本结束。
  • 单步模式会一直保持，直到点“继续”或脚本结束；期间每条语句前都会暂停。

7.7变量监视#

  • 运行中每次变量赋值，右下角“变量监视”面板会新增或更新一行。
  • 点击某个变量的值，会变成输入框；改成新值后回车或失焦，立即写回解释器，后续语句使用新值。
  • 能转成数字的按数字写入，否则按字符串写入。
  • 停止运行后面板自动隐藏。

7.8日志与错误定位#

  • 语法错误：点“检查语法”或输入后自动检查，状态栏显示行号与原因，编辑器高亮错误行。
  • 运行时错误：脚本停止，日志显示“运行时错误: 第 N 行: 原因”，代码页高亮该行，图形页对应积木红色边框闪烁。
  • 常见运行时错误：找图未找到、等待超时、窗口未找到、变量类型不匹配、除数问题（除 0 已处理为 0）。

第 8 章图像、文字与颜色识别#

8.1查找图像#

工作流程：截取整个虚拟屏幕 → 转灰度 → 用模板匹配计算相似度 → 取超过阈值且离参考点最近的匹配中心。

提高成功率的方法：

  1. 截图只保留目标本身，边缘不要带背景、阴影和相邻文字。
  2. 避免截到会变化的内容（时间、计数、动画、光标）。
  3. 保持运行时的缩放比例和截图时一致；换了显示器或缩放后重新截图。
  4. 先看日志里的相似度：接近阈值（如 0.68 对 0.70）说明图是对的，只是阈值略高；差很多说明截图或环境变了。
  5. 目标可能还没出现时，用“等待直到 → 检测到图像”，不要用“查找图像坐标”硬等。

阈值建议：

场景 阈值
同一程序、同一缩放、静态按钮 0.85–0.95
有轻微压缩或抗锯齿差异 0.75–0.85
背景复杂或有轻微遮挡 0.65–0.75
低于 0.6 误匹配风险高，不建议

8.2查找文本#

  • 使用 Windows 自带 OCR，优先简体中文（zh-Hans-CN），不可用时回退英文（en-US）。
  • 每次查找都会截取整个虚拟屏幕并识别，耗时通常在几百毫秒；不要把它放进高频循环。
  • 匹配规则：去掉空格和制表符后做“包含”匹配，忽略大小写；先按行匹配，再按词匹配，最后尝试相邻两行拼接。
  • 返回离参考点最近的匹配中心；参考点越接近目标，越不容易匹配到别处相同的文字。
  • “查找文本坐标”找不到时返回参考点并写警告，不会让脚本停下；“等待直到 → 检测到文本”找不到时只是条件不成立。
  • OCR 只返回文字的位置，不能返回识别出的文字内容；需要读取文字请用其他方式。
  • 小字号、低对比度、艺术字、竖排文字、被遮挡的文字识别率较低；可以放大界面或改用找图。

8.3像素颜色#

  • 返回字符串 R,G,B，例如 255,0,0，不是数字。
  • 适合做“某点是否变红/变灰”的判断：先用比较积木与预期字符串比较。
  • 独占全屏的 DirectX 游戏、受保护视频画面可能取不到真实颜色（返回黑色）。
  • 多屏时坐标同样是物理像素，副屏为负坐标。

8.4多屏、DPI 与坐标#

  • 所有坐标都是物理像素：主屏左上角 (0, 0)，左侧副屏 x 为负，上方副屏 y 为负。
  • 屏幕截图覆盖整个虚拟屏幕，OCR 和找图返回的坐标已经加上了副屏偏移，可直接用于移动。
  • 系统缩放 125% / 150% 不影响脚本，因为取点和执行都用物理像素；但缩放会改变控件外观，截图仍需与运行时一致。
  • 显示器排列或分辨率变化后，旧的绝对坐标会失效，需要重新取点。

9.4自动恢复#

  • 正常关闭主窗口并选择退出时，如果当前停留在脚本编辑器，程序会把所有槽位写入程序目录下的 script_editor_temp.9mcp（包含积木、代码、自定义变量和内嵌图片）。
  • 下次进入编辑器时，如果当前只有一个空槽位，会自动恢复上次的内容，并在日志提示保存时间。
  • 从托盘菜单完全退出等部分退出路径会清除临时文件；因此重要脚本仍建议正式保存为 .9mcp。
  • 临时文件采用“先写 .tmp 再替换”的原子写入，恢复失败时会保留原文件并改名 .corrupt，避免一次中断就丢掉唯一备份。

9.5文件关联#

主程序注册 .9mc 关联；第二实例启动时会把文件参数转发给已运行实例。

场景：循环里 $i 一直不对，想在第 5 次循环时暂停检查。

  4. 在变量监视里查看 $i、$pos 等值，必要时直接修改。
  5. 点“单步”逐条走，确认是哪一步把值改坏。

第 11 章常见问题与已知限制#

11.1脚本运行了但鼠标不动#

  1. 看日志有没有“脚本开始执行”和具体动作；没有动作说明卡在等待条件。
  2. 目标程序是否以管理员身份运行？是的话，编辑器也要以管理员身份启动。
  3. 坐标是否在屏幕内？取点后窗口是否移动过？
  4. 是否被安全软件拦截了模拟输入？可先把脚本换成“移动”测试。
  5. 如果移动仍然只走一小步、或“输入文本”只出现第一个字符，请先确认程序是否为最新版本；旧版本的提前返回缺陷已在当前版本修复。

11.2找图找不到#

  1. 看日志里的最高相似度：接近阈值就调低阈值，差很多就重新截图。
  2. 截图是否包含了会变化的内容或背景？重新裁剪。
  3. 运行时的缩放、分辨率、主题是否与截图时一致？
  4. 图片是否被压缩或拉伸？用 PNG 原图。
  5. 是否在“等待直到 → 检测到图像”而不是“查找图像坐标”？后者找不到会直接停止。

11.3OCR 识别不到#

  1. 系统是否安装了中文 OCR 语言包？没有时程序回退英文，中文识别会失败。
  2. 文字是否太小、太淡、被遮挡或使用了艺术字？
  3. 是否在独占全屏的程序里？先窗口化再试。
  4. 参考点是否离目标太远，匹配到了别处相同的字？
  5. OCR 每次全屏识别较慢，缩小等待频率或改用找图。

11.4等待条件一直不满足#

  • usb：只检测“开始等待后新增”的可移动磁盘；开始等待前已经插好的 U 盘不会触发。
  • key / mouse：50ms 轮询，极短的敲击可能漏掉；按住不放最容易命中。
  • mouse_moved：以第一次检查时的位置为基准，移动距离必须严格大于设定值。
  • window：先按完整标题精确匹配，找不到再按部分标题匹配；标题变了只要包含所填片段仍可命中，但片段过短可能误匹配，尽量填能唯一识别的部分。
  • text / image：缩小参考点范围，检查截图和 OCR。

11.5停止不生效#

  • 停止会取消令牌，等待和移动会在下一个检查点退出；cmd 正在执行时要等命令结束。
  • 如果脚本卡在断点，停止会先自动恢复再取消。
  • 极端情况下弹窗或系统对话框阻塞了输入线程，需要手动关闭对话框。

11.6断点不触发#

  • 嵌套积木的断点已支持：循环、条件、函数内部设置的断点会在对应语句暂停；被注释（禁用）的积木整块不执行，内部断点自然也不会触发。
  • 断点行号是按积木生成的代码估算的；如果代码页被手工大改，行号可能对不上。
  • 条件断点的表达式求值失败时按无条件处理，会每次都停；看日志确认。

11.7安全与合规提示#

  • 只运行来源可信的 .9mc / .9mcp。脚本可以执行 CMD、写剪贴板、控制窗口，等同于可执行程序。
  • 不要把包含账号、密码、激活码的脚本随意分享；脚本包可能内嵌截图。
  • 在游戏、办公、金融等环境中使用前，确认不违反目标软件的服务条款。
  • 长时间运行建议加超时和日志，避免脚本卡死或误操作。
